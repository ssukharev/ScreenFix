# ScreenFix

Утилита для Windows с иконкой рядом с часами: помогает уменьшить изображение по центру монитора и возвращает исходные параметры одним действием. Например, можно приблизить размер изображения на 27-дюймовом экране к 24 дюймам.

В настройках выбираются монитор, его фактическая диагональ и желаемая диагональ. ScreenFix рассчитывает разрешение для уменьшенной области и запрашивает у Windows вывод по центру, сохраняя текущую частоту монитора. Для сохранения пропорций чёрные поля будут со всех четырёх сторон.

## Что нужно

- Windows 10/11, 64-разрядная версия.
- Видеодрайвер с центрированием изображения без масштабирования и подходящим разрешением на нужной частоте.
- Для портативной сборки установка .NET не требуется. Для сборки из исходников нужен .NET 10 SDK на Windows.

Перед включением сигнал должен иметь родное разрешение панели. Например, для панели 2560 × 1440 установите именно 2560 × 1440 в Windows; для 240 Гц сначала выберите 240 Гц. ScreenFix не включает уменьшение поверх уже уменьшенного сигнала.

Драйвер принимает не любой размер, а только из своего списка режимов. Поэтому ScreenFix показывает в списке «Размер изображения» размеры, которые драйвер действительно предлагает для текущей частоты и пропорций монитора, и по умолчанию («Авто») включает ближайший к желаемой диагонали. Например, для 27″ → 24″ на панели 1920 × 1080 точный расчёт даёт 1704 × 960, но такого режима у драйверов обычно нет. Тогда будет предложен 1768 × 992 (≈ 24,85″) или 1600 × 900 (22,5″). Фактическая диагональ всегда показана рядом.

ScreenFix проверяет результат и откатывает изменение, если драйвер растянул картинку или снизил частоту. Приложение не подменяет 240 Гц незаметно меньшей частотой и не добавляет пользовательские тайминги в видеодрайвер.

## Запуск

1. Распакуйте `ScreenFix-win-x64.zip` в отдельную папку. Для Windows на ARM используйте сборку `win-arm64`.
2. Запустите `ScreenFix.exe`. Права администратора обычно не нужны.
3. Выберите нужный монитор и укажите его настоящую диагональ, например `27`. Укажите желаемую — например `24`.
4. Проверьте предложенный размер и его фактическую диагональ. При необходимости выберите другой размер в списке «Размер изображения». Размер, выбранный вручную, пробуется один; в режиме «Авто» при отказе драйвера пробуются и другие близкие размеры.
5. По желанию нажмите «Проверить режимы»: ScreenFix спросит у драйвера, какие размеры он принимает, не меняя экран.
6. Включите уменьшение. Если картинка правильная, подтвердите её в течение 15 секунд; без подтверждения ScreenFix вернёт исходные параметры.

Если драйвер отклонил режим, начните с рекомендаций ниже. Совместимость с конкретной видеокартой проверяется на Windows.

После закрытия окна приложение остаётся в трее. Если иконки не видно, откройте скрытые значки рядом с часами.

## Управление

| Действие | Управление |
| --- | --- |
| Включить / выключить выбранный режим | Меню иконки в трее или `Ctrl + Alt + F10` |
| Вернуть исходные параметры | Меню иконки в трее или `Ctrl + Alt + F11` |
| Открыть настройки | Иконка в трее |
| Завершить приложение и восстановить экран | «Восстановить экран и выйти» в меню трея |

Горячая клавиша может быть занята другой программой; в этом случае используйте меню трея. При выходе ScreenFix восстанавливает параметры, сохранённые перед включением. Отдельный процесс следит за приложением и пробует восстановить режим, если основной процесс завершился аварийно. Резервная копия сохраняется в `%LocalAppData%\ScreenFix\recovery.json` для повторной попытки при следующем запуске.

Снимок восстановления действует в том же сеансе Windows и для тех же подключённых устройств. После переподключения оборудования или перезагрузки идентификаторы могут измениться: тогда ScreenFix откажется применять старый снимок и сохранит файл для диагностики. Изменения ScreenFix временные и не записываются в постоянную конфигурацию видеодрайвера; при перезагрузке Windows загружает постоянную конфигурацию мониторов.

Если старый снимок больше не подходит, сначала проверьте разрешение, частоту и расположение мониторов в настройках Windows, затем нажмите «Принять текущий экран как исходный». Эта кнопка архивирует старую копию и позволяет включить новый профиль; параметры экрана она не меняет.

Аварийное восстановление из папки приложения:

```powershell
.\ScreenFix.exe --restore
```

Для обращения по поводу ошибки сохраните диагностику через окно приложения или запустите `ScreenFix.exe --diagnostics`.

## Второй монитор и курсор

При центрировании средствами драйвера чёрные поля находятся за пределами рабочего стола: курсору не нужно пересекать их как обычную область Windows. ScreenFix умеет придвигать соседний монитор в виртуальной раскладке Windows к краю уменьшенной области, чтобы между экранами не оставалось пустого промежутка. Этот переход можно включить в настройках.

Переход действует в обе стороны. Если игра захватила курсор, ScreenFix не снимает захват и не вмешивается в управление прицелом. Для перехода на другой монитор сначала освободите курсор, например через `Alt + Tab`.

## CS и полноэкранный режим

Изменение режима применяется к выбранному монитору средствами Windows. ScreenFix не требует настройки под конкретную игру, не внедряется в процесс CS и не перекрывает края изображения чёрными окнами.

Однако полноэкранная игра может сама переключить разрешение и масштабирование. В таком случае выберите в CS то же уменьшенное разрешение и нужную частоту, а в видеодрайвере — центрирование без растягивания. Один внешний процесс не может гарантированно сохранить размер изображения при любом поведении полноэкранной игры и любого драйвера. Если CS или другая программа изменит режим, ScreenFix обнаружит это, отключит уменьшение и попытается восстановить параметры с предупреждением. Он не будет непрерывно переключать экран во время матча.

Размер зависит от разрешения панели и режима вывода. Для панели 1920 × 1080 и перехода 27″ → 24″ точный расчёт даёт 1704 × 960 пикселей (≈ 23,97″), на панели 2560 × 1440 — 2272 × 1280. Такие размеры работают, только если драйвер их перечисляет (например, вы создали пользовательское разрешение). Иначе включается ближайший доступный размер из списка. Выбор любого меньшего разрешения даёт свою эффективную диагональ. Приложение опирается на введённую диагональ, поэтому её нужно указать правильно.

Чтобы CS показывала именно этот размер, выберите в игре то же разрешение: оно есть в списке игры, раз его предлагает драйвер.

## Если драйвер отклоняет уменьшение

Сообщение вроде «Код Windows 1610» означает, что видеодрайвер не смог собрать запрошенный режим с центрированием. Это не повреждение данных, исходные настройки при этом не меняются. Сначала ScreenFix сам пробует несколько близких размеров и несколько способов включения (CCD, классический CCD, `ChangeDisplaySettings`), поэтому сообщение появляется, только если не подошёл ни один.

1. Верните родное разрешение панели и нужную частоту в Windows. Убедитесь, что выбран правильный монитор и включён режим «Расширить эти экраны».
2. В панели видеокарты включите центрирование. В NVIDIA: «Регулировка размера и положения рабочего стола» → «Масштабирование: Без масштабирования» и «Выполнять масштабирование на: ГП». Названия зависят от драйвера.
3. На ноутбуке с гибридной графикой смотрите строку «видеоадаптер» под списком мониторов. Если монитор работает через встроенную графику Intel или AMD, настройки NVIDIA на него не действуют: настройте масштабирование в приложении встроенной графики или подключите монитор к порту, который работает от дискретной видеокарты (часто это HDMI). Это зависит от ноутбука.
4. Нажмите «Проверить режимы»: в ответе видно, какие размеры принимает драйвер. Размеры, отмеченные ✓, можно включать.
5. Чтобы получить точный расчётный размер (например, 1704 × 960), создайте такое пользовательское разрешение в панели видеокарты, сохранив частоту. После этого оно появится в списке ScreenFix. Драйвер и монитор могут не поддерживать такой режим; ScreenFix этого не гарантирует.
6. Если проблема сохраняется, нажмите «Сохранить диагностику» и отправьте файл. В нём указаны видеоадаптер, список режимов и ответ драйвера на каждую попытку. Подробности попыток есть и в `%LocalAppData%\ScreenFix\ScreenFix.log`.

## Сборка из исходников

В Windows установите .NET 10 SDK, откройте PowerShell в папке проекта и выполните:

```powershell
dotnet run --project tests/ScreenFix.Core.Tests/ScreenFix.Core.Tests.csproj --configuration Release
dotnet run --project tests/ScreenFix.Display.Tests/ScreenFix.Display.Tests.csproj --configuration Release
dotnet run --project src/ScreenFix.Windows/ScreenFix.Windows.csproj
```

Создать портативный архив для обычного ПК:

```powershell
.\scripts\Publish-Portable.ps1
```

Собрать обе архитектуры:

```powershell
.\scripts\Publish-Portable.ps1 -Runtime win-x64,win-arm64
```

Результат — `artifacts/ScreenFix-win-x64.zip` и, при выборе ARM, `artifacts/ScreenFix-win-arm64.zip`. Скрипт сначала запускает оба набора проверок: расчёты размера и переходов, структуры взаимодействия с Windows и расчёты конфигурации мониторов. Затем он публикует самостоятельную сборку .NET с одним исполняемым файлом. WPF не обрезается; необходимые нативные компоненты могут распаковываться во временную папку при запуске. GitHub Actions также запускает оба набора проверок и собирает Windows x64 архив.

Оба набора проверок можно запустить на macOS/Linux, но запуск WPF, переключение монитора, работа трея и проверка с CS требуют Windows и реального оборудования. Успешная сборка и автоматические проверки не заменяют проверку на конкретном мониторе и видеокарте.
